# 数学建模论文检查与定向修订

`paper-content-review` 是论文内部质量与跨章节一致性的协调入口。它不以材料数量划分
`quick/full` 模式，也不要求先形成完整论文：根据用户意图、指定范围和现有材料，
只运行能够产生可靠结论的检查；材料不足时降低核验强度，不冻结无关模块。

开始前读取 [references/review-contract.md](references/review-contract.md)。选择专项模块时
读取 [references/initial-review-routing.md](references/initial-review-routing.md)；建立、合并
或更新问题时读取 [references/issue-ledger-schema.md](references/issue-ledger-schema.md)。
用户指定 CUMCM/国赛且需要检查可见格式或适配模板时，再读取
[references/cumcm-format.md](references/cumcm-format.md)。

## 任务识别

先识别三个互不绑定的维度：

```text
任务意图
  review   只检查并给出问题，不修改正文
  revise   修改用户明确授权的问题编号或文本范围
  write    根据已知材料新写指定章节或论文

检查范围
  用户指定的章节、子问题、段落、公式、图表或引用
  完整论文
  用户未限定范围时，由论文内容和请求合理确定相关范围

专项模块
  通用内部质量、摘要、问题重述、问题分析、模型假设、符号说明、
  参考文献元数据、正文引用支持
```

“全文”只是检查范围，不是一种特殊状态。“快速检查”只表示优先报告高风险问题；
除非用户明确只要初筛，否则完成所选范围内能够执行的检查。

用户已经明确提出“检查摘要”“检查第四问”等请求时，直接执行只读检查，不要求再次
确认。只有请求过于含糊且不同选择会实质改变工作量或结果时，才询问范围。修改正文、
重算结果或扩大修改范围始终需要明确授权。

## 已知材料

按内容识别文件，不要求固定文件名：

```yaml
paper: 完整论文或当前已完成的正文部分
problem: 赛题、子问题与附件说明
section: 摘要、重述、分析、假设、符号表或其他待检查章节
model: 模型推导、算法、代码说明或研究路线
results: 求解、验证、敏感性分析和最终结果
dataset: 原始数据、清洗结果或中间数据
figures: 图片、图表及说明
references: 参考文献列表、BibTeX 或引用信息
editable_source: 可直接修改的 LaTeX 或其他源文件
rules: 可选；比赛格式、模板和提交规则
ai_policy: 可选；交给后续 AI 合规验收
```

事实冲突按“用户最新明确说明 > 官方题面或规则 > 可复现结果 > 模型与分析草稿”处理，
并报告无法消解的冲突。不得猜测数据、模型、结果、规则、参考文献或作者意图。

## 路由原则

1. 用户明确点名专项时，只运行该专项及直接决定其正确性的通用检查。
2. 用户指定多个方面时，运行对应模块并合并结果。
3. 用户要求全文检查时，根据论文实际内容和现有材料启用适用模块，不机械要求全部专家。
4. 单章节任务可由对应专家直接完成，不必经过 `paper-content-review`。
5. 涉及多个章节、跨模块冲突、统一编号或多处修改时，由 `paper-content-review` 协调。
6. 缺少某项材料时，只把依赖该材料的判断标为“待核实”或“无法核验”；仍执行能够由现有材料支持的检查。
7. 专项不可用时，只做 `paper-content-review` 能可靠完成的轻量检查，并明确未完成深度核验。

## 通用内部质量检查

`paper-content-review` 只负责专项之外或跨模块的问题：

- 题目任务与论文位置、回答和输出是否对应；
- 指定范围是否形成“分析—模型—求解—结果—解释—验证”闭环；
- 变量、目标函数、约束、算法与结果解释是否兼容；
- 摘要、正文、表格、图注和结论中的数值、单位与结论是否一致；
- 数据来源、处理、样本范围、参数和结果是否可追溯；
- 验证、误差、敏感性或稳健性分析是否足以支持结论；
- 图表、公式和附录是否被正文正确引用并得到解释；
- 修改一个模块可能造成的跨章节连锁影响。

摘要、重述、分析、假设、符号和文献的深度诊断由对应专家负责；父 Skill 不复制其详细
检查表。同一根因只保留一个主问题，跨模块表现写入证据、影响范围或关联问题。

## 范围纪律

范围检查只报告指定范围内的问题，以及直接导致该范围结论错误、无法验证或与题面冲突的
跨范围依赖。跨范围依赖必须明确标记，不能顺带审查其他章节，也不构成修改其他章节的授权。

格式规范只在用户要求格式检查、写作适配或相关格式事实直接影响当前内容时使用。
`paper-content-review` 可以提示明显格式与提交风险，但最终 AI 使用、匿名、文件命名、提交资格和
当届格式合规由 `paper-format-consistency-audit` 验收；评分与位次由 `bzd-review-paper` 独立判断。

## 检查输出

检查默认只读，依次给出：

1. 已读取材料、检查范围与启用模块；
2. 当前范围的内部质量结论；
3. 按 P0—P3 排序的统一问题账本；
4. 直接相关的跨范围依赖与关联；
5. 无法核验项目及所缺材料；
6. 建议处理顺序；
7. 提示用户可通过问题编号或文本范围授权修改。

未发现问题时明确记录相应模块通过，不为填充报告制造缺陷。不得在初审中声称论文已经
满足全部竞赛要求、AI 使用最终合规或必然获得某等级奖项。

## 专家直接修订

用户可以直接要求某个专家检查或修订其负责范围。专家默认执行 `review`；只有以下表达
构成 `revise` 授权：

```text
修改摘-02
只修改摘要第二段
按析-01重写问题二的分析段
统一公式(12)及其后一段中的符号
```

“继续”“按建议处理”“完善论文”“把问题修好”不构成大范围修改授权。专家修订时：

1. 只修改本模块中明确授权的编号或范围；
2. 保留已确认的模型、数值、结论和引用，不编造缺失事实；
3. 发现跨模块同步需求时先列出位置和原因，不自动扩大修改范围；
4. 修改后复核本模块及必要的跨章节一致性；
5. 保留原问题编号并更新修复状态。

多模块修改、同一根因跨越多章或需要统一源文件差异时，由 `paper-content-review` 协调处理。

## 源文件修改

有可编辑源文件时，确认主文件、章节文件和引用关系，只编辑授权范围，避免全文件格式化；
修改后检查差异、语法、标签、交叉引用和图片路径，本地有编译器时编译验证。只有 PDF、
Word 或不可编辑文本时，只提供授权范围的替换文本，不声称已修改源文件。

缺少数据或结果时使用明确占位，不伪装成已完成：

```latex
\textbf{[待补充：请提供参数扰动范围及对应结果，以完成灵敏度分析。]}
```

## 工作流程

```text
读取用户指定材料
  -> 判断 review / revise / write
  -> 确定范围和适用模块
  -> 按各模块现有材料执行
  -> 输出或更新统一问题账本
  -> review 到此停止
  -> 用户明确授权后定向修改
  -> 复核受影响模块和必要的全局一致性
  -> 更新原编号状态并整理后续交接
```

这个流程保留检查与修改的授权边界，但不以 `quick/full` 或三材料组合控制能否开始。

## `write` 模式

用户明确要求从头撰写论文或章节时，根据已知题面、模型、结果、图表和参考文献写作；
数值与结论必须可追溯。默认交付 LaTeX 文本，只有用户要求文件时才创建文件。保留官方
模板的文档类、宏命令和章节入口，不生成虚构数据、结果、引用或图片路径。

## 修改后交接

初审和授权修改完成后，可整理进入 `paper-format-consistency-audit` 所需的论文版本、题面、格式规范、
AI 使用规范、可选数据集和未解决问题编号。终审使用冻结版本独立评分；论文发生实质
修改后，原评分失效。

## 交付前检查

1. 没有残留旧式速度分级状态机或三材料全局门禁。
2. 用户点名章节时已直接路由对应专家，没有要求完整论文或格式规范。
3. 材料不足只限制相关结论，没有冻结无关模块。
4. 专家直接检查默认只读，直接修改具有明确编号或范围授权。
5. 所有问题使用稳定中文模块编号，严重度、核验状态和修复状态相互独立。
6. 同一根因已去重，跨范围依赖没有被当成扩大修改授权。
7. 修改后只复核受影响模块和必要一致性，没有默认重跑全部专家。
8. 初审没有越权作最终合规、评分或奖项判断。
