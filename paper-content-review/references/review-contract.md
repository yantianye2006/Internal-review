# 检查、修订与专家协作合同

本合同约束父 Skill `paper-content-review` 和直接或编排调用的专项专家。专业诊断规则由各专家维护；
本合同只统一任务边界、范围纪律、问题记录、修改授权和复核方式。

## 任务边界

```text
review  只读检查，输出问题和建议，不修改论文
revise  修改用户明确指定的问题编号或文本范围
write   用户明确要求时，从已知材料生成指定内容
```

用户提出检查请求后可以直接执行 `review`，不需要再次请求检查授权。任何正文修改、文件
写入、结果重算或范围扩张都不能由检查请求自动推导。

`quick/full` 不是任务模式。用户要求快速时优先报告高风险问题；用户要求全文时将全文
作为范围，并按实际内容启用相关模块。

## 材料原则

- 不设置完整论文、题面、格式规范三者同时齐全的全局门禁。
- 每个模块根据自己的最低材料执行，详见 `initial-review-routing.md`。
- 现有材料不足以确认某项结论时，标记“待核实”或“无法核验”，不得猜测。
- 只冻结缺少必要输入的具体判断，不冻结其他模块或整个初审。
- 格式规范不是摘要、重述、分析、假设、符号或引用内容检查的通用启动条件。

## 调用方式

### 父 Skill 编排

`paper-content-review` 根据用户范围调用一个或多个专家，负责跨章节检查、问题合并、去重、统一排序
和多模块修改协调。用户点名模块时只调用相关专家；全文请求按论文实际章节启用模块。

### 专家直接调用

专家可以独立接受 `review`、`revise` 或其支持的 `write` 请求：

- `review` 默认只输出本模块问题和核验限制；
- `revise` 只修改明确授权的问题编号或文本范围；
- 专家使用与父 Skill 相同的中文编号和问题字段；
- 直接调用产生的编号在后续编排审查中继续沿用；
- 发现跨模块影响时记录依赖，不擅自检查或修改范围外内容。

## 范围纪律

用户指定章节、子问题、段落、公式、图表或引用时，只处理该范围。范围外内容只有在直接
造成当前范围错误、无法验证或违反题意时才作为“跨范围依赖”报告。跨范围依赖不是修改授权。

## 严重度与状态

严重度：

- `P0`：现有材料直接确认的硬性资格或提交风险；初审只作风险记录，最终交给二审核验。
- `P1`：题目任务未完成、核心模型不成立、关键结果错误或主要结论无法支持。
- `P2`：假设、推导、数据、符号、验证、引用或重要论证存在实质缺陷。
- `P3`：表达、局部结构、一般格式或可读性问题。

核验状态：`已确认 / 待核实 / 无法核验 / 已排除`。

修复状态：`未处理 / 已修复 / 部分修复 / 仍需材料 / 需重新计算 / 需作者确认`。

三类字段必须分别记录，不能用严重度代替证据强度或修复进度。

## 专家返回

专家返回本模块问题和 `通过 / 有问题 / 不适用 / 无法核验` 状态。编排调用时不输出第二份
总体报告；直接调用时可以输出简洁的单模块结论，但不得作全文提交资格或奖项判断。

检查阶段不重写正文、不创建未经请求的替换稿，也不生成无关旁支产物。需要修改时等待
用户明确指定编号、章节、段落、公式、图表或原文范围。

## 修改与复核

1. 只修改授权范围，不顺手修复其他问题。
2. 依赖其他位置同步变化时，先列出依赖并请求授权。
3. 修改后保留原问题编号，更新修复状态。
4. 复核直接受影响专家和必要的跨章节一致性，不默认重跑全部模块。
5. 有源文件时检查差异和语法；无源文件时只提供替换文本。

## 职责分离

`paper-content-review` 和专项专家负责内部质量、章节诊断与授权修订。明显格式或提交风险可以提示，
但 AI 使用、匿名、文件命名、正式提交资格和当届整体合规由 `paper-format-consistency-audit` 最终验收；评分、
奖项与位次由 `bzd-review-paper` 独立判断。
