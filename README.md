# Internal Review

数学建模论文提交前的“三审机制”组合 skills：先查内容，再查格式与一致性，最后做竞赛评委式评分和提交对齐。

## 三审机制

```text
完整赛题 + 论文草稿
        │
        ▼
一审：paper-content-review
内容、逻辑、模型、数据与章节闭环
        │ 修复并冻结版本
        ▼
二审：paper-format-consistency-audit
格式、AI 使用、数据真实性、全文一致性与结果合理性
        │ 形成终稿候选
        ▼
三审：bzd-review-paper
评委式打分、竞赛要求对齐、位次估计与优先修改建议
```

## 一审：`paper-content-review`

原名 `essay-test`，这里改成了更能说明职责的 `paper-content-review`。

它负责论文内容层面的初审，可以针对一个章节、一个问题、一个公式，也可以检查全文。主要检查：

- 题目任务是否被正确理解并逐问回答；
- “问题分析—模型—求解—结果—解释—验证”是否形成闭环；
- 变量、目标函数、约束、算法、参数和结果解释是否相互兼容；
- 摘要、正文、图表、结论中的数字、单位和结论是否一致；
- 数据来源、处理规则、参数和结果是否可追溯；
- 验证、误差、敏感性和稳健性分析是否足以支撑结论；
- 图、表、公式和附录是否被正文正确引用和解释。

它默认只读，使用者必须明确授权后才修改指定问题编号或文本范围。一审的结果是一个稳定的问题账本，供二审和后续修订使用。

调用示例：

```text
使用 paper-content-review 检查这篇数学建模论文的全文内容。
重点检查每个子问题是否完成“任务—模型—求解—结果—验证”闭环，
把问题按 P0-P3 编号并给出证据位置，不要直接修改正文。
```

## 二审：`paper-format-consistency-audit`

原名 `ai-detector`，改名是为了避免把它误解成单纯的 AI 文本检测器。它实际是按 26 项自检表执行的论文格式与一致性审查，AI 合规只是其中一个维度。

它要求四类材料齐全后才开始：

1. 被检查论文；
2. 比赛格式规范；
3. AI 使用规范；
4. 题目。

数据集或题目附件是可选输入。二审重点检查：

- 格式、篇幅、字体、版式、摘要、匿名和提交要求；
- AI 使用边界、披露义务和合规风险；
- 数据来源、图表、计算结果和论文文字之间的一致性；
- 模型逻辑、结果合理性和需要原始数据才能核验的项目；
- 全文 26 项自检表的逐项状态、证据位置和整改建议。

它只输出 `合格`、`存在问题` 或 `待核实`，不根据文风单独断言作者身份，也不把缺少数据证据直接伪装成失败。最终会生成独立的 UTF-8 HTML 审查报告。

调用示例：

```text
使用 paper-format-consistency-audit 对终稿候选进行二审。
我会提供论文、当届格式规范、AI 使用规范和完整题面。
请逐项完成 26 项检查并生成 HTML 报告，不要把无法由材料确认的项目判为失败。
```

## 三审：`bzd-review-paper`

`bzd-review-paper` 是社区 BZD 数模社开发的评委式论文评分 skill。它不是简单的“读后感”，而是先根据完整赛题冻结问题要求和评分框架，再对论文进行证据中心的百分制评分。

它可以输出：

- 论文质量原始得分；
- 格式质量系数和最终得分；
- 按问题、模型建立、模型求解、结果与回答定位的逐项扣分；
- 资格与格式审查；
- CUMCM 场景下的竞赛环境校准和位次估计；
- 3—5 条按预期收益排序的提交前修改建议；
- 自包含的中文 HTML 评委报告。

使用时要注意：

- 必须提供完整赛题和完整论文；
- 首次使用要明确是否为高教社杯全国大学生数学建模竞赛；
- 还要选择是否启用严格的 `bzd-paper-format-checker` 格式审查；
- 竞赛位次是基于校准信息的估计，不是官方排名保证；
- 论文修改后，原评分不再代表新版本。

调用示例：

```text
使用 bzd-review-paper 对这篇终稿进行三审。
这是高教社杯全国大学生数学建模竞赛国赛，题型为 B 题。
请先询问并记录是否启用严格格式审查，然后生成中文 HTML 评委报告、逐项评分和优先修改建议。
```

## 推荐使用顺序

### 第一次：内容问题账本

先使用 `paper-content-review`。如果论文还在写作阶段，可以只审查摘要、问题分析、模型假设、某一问或某一组公式，不必等待全文完成。

### 第二次：终稿材料审查

根据一审问题账本完成修订，准备论文、题面、格式规范和 AI 使用规范，再运行 `paper-format-consistency-audit`。所有无法确认的项目要保留为“待核实”，并人工补证据。

### 第三次：模拟提交前评委

在二审问题处理后，冻结一个版本，再运行 `bzd-review-paper`。不要把三审报告中的预估奖项或位次写成论文结论；它的用途是帮助排序最后几项修改工作。

## 安装

```bash
git clone https://github.com/yantianye2006/Internal-review.git
```

可将三个子目录分别复制到 Codex、Claude Code 或其他 agent 的 skills 目录；也可以使用仓库根目录的 `SKILL.md` 作为组合入口。

## 与 BZD 系列 skills 的关系

本仓库只收录 `bzd-review-paper` 作为第三审。BZD 社区还维护一组更细的专项检查 skill，例如摘要、问题重述、问题分析、模型假设、符号说明、模型求解、AI 工具声明、参考文献与附录等。需要更细的局部诊断时，可从 [BZDmathclub/bzd-math-modeling-skills](https://github.com/BZDmathclub/bzd-math-modeling-skills) 获取完整系列。

感谢 BZD 数模社及其社区贡献者把历年竞赛评阅经验、评分观察点和竞赛环境校准整理成可调用的 skill。BZD 官方入口和使用说明见 [bzdshumo.com](https://bzdshumo.com/)。

## 开源与文件说明

- 本仓库只保留三审工作流及其检查规则，不再捆绑历史遗留的 Typst 论文模板、字体、logo 或 PDF 图片资源。论文排版模板不影响内容审查流程；如需排版，请在独立模板仓库或用户自己的项目中配置。
- 不要向仓库提交未公开赛题、未授权论文、个人身份信息、API Key、Token 或内部材料。
- BZD 的评分规则、历史校准数据和竞赛要求可能随年份变化，使用时应核对当届官方规则。
- 三审机制只能辅助判断，不能替代队伍成员对题意、数据、模型和最终提交材料的人工核验。
