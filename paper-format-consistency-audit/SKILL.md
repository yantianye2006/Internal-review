# Paper Format and Consistency Audit

按 [26 项自检表](references/checklist.md) 审查数学建模竞赛论文，并生成以完整自检表为主体的简洁 HTML 报告。

## 输入门禁

开始审查前，先确认以下四类材料均已提供且可读取：

1. 被检查论文；
2. 格式规范；
3. AI 使用规范；
4. 题目。

数据集或题目附件为可选输入。按材料的实际内容判断类别，不仅依赖文件名；同一文件只有在内容明确覆盖多个类别时才可同时满足多个输入项。

只要任一必备材料缺失、内容不完整到无法适用或文件不可读取，立即冻结审查：

- 不进行部分审查；
- 不推测或自行补齐缺失规则；
- 不生成 HTML 报告；
- 仅返回“审查已冻结”、缺失或不可读的项目清单，以及请用户补充材料的简短提示。

## 审查规则

输入齐全后，完整读取四类必备材料和用户提供的数据集，再读取 [26 项自检表](references/checklist.md)。逐项填写全部 26 条，不得合并或省略。

材料优先级如下：

- 格式规范决定篇幅、字体、版式、摘要、匿名等格式要求；
- AI 使用规范决定 AI 使用边界、声明义务与违规标准；
- 题目及其附件决定任务、约束、原始数据和交付要求；
- 被检查论文是审查对象；
- 数据集用于复核来源、计算、图表和结果一致性；
- 自检表提供审查维度。自检表中的示例阈值若与用户提供的规范冲突，以用户提供的规范为准，并在对应行说明依据。

每项结果只能是：

- `合格`：材料中有充分证据满足该项；
- `存在问题`：有明确证据违反要求或前后不一致；
- `待核实`：现有材料不足以可靠判断，或需要无法执行的外部/人工核验。

对每一项：

- 给出可定位的位置，优先使用页码，并补充章节、段落、图、表或公式编号；
- 问题简述只陈述证据支持的事实；
- 整改建议应具体、最小且可执行；
- 合格项的“问题简述”可写“未发现问题”，“整改建议”写“无需整改”；
- 无法定位时明确写“未定位”，不得编造页码；
- 不因文风或 AI 检测器分数单独断言作者身份或违规。仅有风格信号时标记为“待核实”，并说明需要的核验材料；
- 没有数据集时仍继续审查，但凡必须依赖原始数据才能确认的条目应标为“待核实”。

## HTML 报告

在当前工作区生成一个 UTF-8 编码、可独立打开的 `.html` 文件。默认命名为 `AI检测自检报告.html`；若同名文件会覆盖用户文件，则采用带时间或论文名的唯一文件名。

报告保持简洁，并按以下结构输出：

1. 标题与审查对象；
2. 输入材料清单；
3. 结果汇总：26 项中合格、存在问题、待核实的数量，以及最优先整改事项；
4. 主体自检表，列为：一级维度、序号、核查条目、核查结果、问题位置、问题简述、整改建议；
5. 一段简短结论。

主体表必须包含 [26 项自检表](references/checklist.md) 的全部六个一级维度和 26 个条目。使用语义化 HTML、`lang="zh-CN"`、内嵌 CSS 和适合打印的样式；不得依赖外部资源或 JavaScript。对文件名、论文内容和用户文本进行 HTML 转义。用颜色辅助区分三种结果，但不得仅依赖颜色表达状态。

完成后核对：表格恰有 26 个审查条目，三类结果计数之和为 26，汇总数字与表格一致，所有“存在问题”和“待核实”项均有位置或未定位说明、问题简述及建议。最后向用户提供生成的 HTML 文件链接和一句结果摘要。
